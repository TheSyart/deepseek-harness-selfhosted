# Agent Note: The Electron desktop carrier — file:// plus IPC, the `webServer` facade, and the desktop bridge

Status: implemented

English | [中文](2026-08-10-electron-desktop-ipc-carrier.zh.md)

## Problem

The web client architecture splits the browser GUI into a host-served client plugin tree and a React-free object layer, and its loading chain, slots, and services are carrier-independent. Only the carrier differed for a desktop shell, and the docs already reserved the shape: [web-server.md](../../../../docs/subsystems/web-server.md) states that Electron loads the built files over `file://` and sends fetch requests through an IPC bridge instead of the HTTP server. No desktop surface existed, so the decision was what the carrier — profile composition, host-side bridge, renderer-side transport — would be, without touching the client contract.

## Decision

**The desktop profile reuses the entire client roster and replaces only the transport.** `dsh --profile desktop` stacks `dsh-base`, `dsh-web-app`, then the new `@deepseek-ai/dsh-desktop` bundle, whose patch disables `webserver`, `web-startup`, `web-runtime`, and `client-hmr`, replaces the `connection` row's `inject` with `[]` (the removed `web-runtime` row was its `webRuntime` provider), and inserts `desktop-runtime` plus `desktop-bridge`; the bridge row injects `desktopStartup`, `clientModules`, `apiProxy`, and `connection` and disables itself under plain Node via `disabled: !!js ctx.get('desktopStartup') === undefined`. The Electron window loads the built renderer dist over `file://`, and every wire need — `/api`-shaped fetch (unary RPC plus the apiproxy SSE-codec downlink streams), plugin client bundles, and the client boot graph — rides five `ipcMain` channels. The bridge serves each fetch through the connection node half's `createSharedFetchHandler` with the apiproxy handler as its fallback — the same interceptor-first order the web `/api` route uses, so Typert Remote endpoints such as `pluginInventory/list` resolve on the desktop exactly as on the web; the fallback answers the `events.mux`/`events.host` GETs with the SSE codec where the web route answers upgrade-required, because no WebSocket exists over IPC. The renderer-side half of the swap is the [connection in-process transport seam](2026-08-10-connection-in-process-transport-seam.md). The composition listens on no HTTP port at all.

**`desktop-runtime` provides a composition-satisfying `webServer` facade, not a modified `modules`/`connection` inject.** The mounted `modules` and `connection` node halves bind their route registrations and index tap to `webServer`, so `DesktopWebServerFacade` accepts `register`/`registerUpgrade` as no-op seats (the bridge serves those paths), keeps `tapIndex`/`applyIndexTaps` real (the app applies them when it renders its own index), reports the loopback `host` (the directory-picker resolver reads it to select the native chooser), and throws from `port` and `registerFallback` because no server exists. Keeping the mounted rows' contract untouched is what lets one provider swap keep working under both carriers.

**The bridge is gated on a launcher-provided `desktopStartup` service.** The app assembly provides it before any config row mounts; it carries the Electron `ipcMain` surface and `validateSender`, the trust fence that accepts only a `senderFrame` whose URL starts with the app dist directory URL. Every channel handler checks the sender first, and all channel registrations plus open streams unwind in one effect with the plugin fiber.

**The renderer wrapper subscribes once, before any invoke, and buffers per-stream messages.** The bridge starts pumping a response body as soon as the main-process fetch resolves, which can precede the invoke receipt; a per-fetch subscription registered after the receipt would drop every message sent in that gap, so `createIpcFetch` holds one stream-channel subscription and adopts each receipt's queued messages once it arrives. The wrapper also routes `file:///api/...` URLs to the bridge: the connection client derives its base from `location.origin`, and Chromium reports the origin `file://` for file pages, so relative `/api` paths resolve against `file://` rather than the in-process `dsh.internal` authority. The installed transport sets `localAuthority: true` because every IPC channel enforces the main-process sender fence; `file://` alone grants nothing. This lets the renderer use Host-backed settings while a permission-restricted remote browser remains process-local.

**The model-visible orientation is the `app:desktop-surface` prompt section** (order -98), registered by `desktop-runtime`; its text names the desktop app as the interaction surface and states the in-process IPC transport with no HTTP port. Snapshot coverage matches the web surface's `app:web-surface`: that section has no dedicated keyless snapshot either, and the desktop section's assembled text is pinned verbatim by the package test (`packages/bundle/desktop/tests/desktop-runtime.spec.ts`).

## Alternatives considered

**Reuse the webserver row — serve the dist over HTTP on a loopback port.** Rejected: the reserved design for Electron is literal `file://` plus IPC, and a loopback HTTP listener would make the desktop surface indistinguishable from the browser one — same port discovery, same TLS-less network surface, same URL line — for no desktop benefit.

**Modify the `modules` and `connection` node halves to drop their `webServer` bindings on desktop.** Rejected: that forks two composition shapes for production rows, doubling every future change to those halves. The facade keeps both halves byte-identical and their transport contract intact — the carrier swap is invisible to them.

**Register an `app://` custom protocol with `protocol.handle`.** Rejected: the docs reservation spells `file://` plus IPC, and a custom scheme would add a second renderer loading path plus new URL semantics — and the renderer keeps no Electron-specific entry beyond the preload, which a custom scheme would have to mint and defend. `file://` plus the rewritten `dsh-bundle:///<id>?rev=` graph URLs needs nothing the module system does not already do.

**Chunked request-body upload over the bridge.** Deferred, not rejected: the fetch request body crosses IPC as one structured-clone copy (base64), so a large attachment POST duplicates its body in memory for the transfer; a chunked path can land later without changing the channel contract.

## Consequences

The desktop surface is a patch layer plus two plugins over the same client roster, and the renderer runs the same web shell kernel; UI features, slots, and the object layer inherit every browser-side behavior, including `?fixture` and reconnect semantics. The facade's `port` throw means any row that genuinely needs a server port must compose the real webserver row — the failure mode is loud at first read. The bridge row's self-disable keeps plain-node `dsh --profile desktop` a valid windowless, portless composition. Accepted costs: no client-plugin HMR channel (the `client-hmr` row stays disabled; config-only hot reload still applies), and the single-copy request-body bound recorded in the [bundle README](../../../../packages/bundle/desktop/README.md).
