# Agent Note: 全局 Token 用量是基于逐调用投影的 Host 报告

Status: implemented

[English](2026-08-23-global-token-usage-settings.md) | 中文

## 问题

现有 `tokenUsage` 投影回答的是另一个问题：它向浏览器客户端提供单个会话的最新汇总。全局设置报告需要实时、持久、已归档及子 agent 会话中每次提供方上报调用的日期与精确路由。把普通会话列表值相加无法恢复这些维度，还会重复计算分叉中复制的父历史。每隔 30 秒刷新浏览器时重放所有存储日志虽然正确，但运行代价浪费。缺失用量必须保持缺失；启发式 token 估算对上下文压力有用，却不是提供方测量值。

## 决策

`@deepseek-ai/dsh-token-meter` 拥有第四个投影 `tokenUsageTimeline`，因为提供方用量的替换语义本来就归它负责。该投影仅限 Host：它有持久检查点，但没有客户端 wire 值，因此绝不会进入 `session.list` 或实时投影帧。每个 `(turn, step)` 保留一条样本，包含首次用量 seq、`step/start` 时间、请求标头中的精确路由或明确的未知路由，以及四个互斥 bucket。后续累计用量只替换 bucket，不改变归属信息；失败前上报的用量仍会保留；推理不会再次加到输出。反向链接的定长块让实时追加不随总历史长度增长，而仅 detach 检查点策略避免在每次实时周期检查点中序列化不断增长的时间线。

首次用量 seq 是分叉的所有权标记。全局汇总排除 seq 小于该会话标头 `seedLength` 的样本；原始会话继续是复制父调用的唯一拥有者。因此删除原始会话会从报告中移除这些调用，而不会把所有权转给仍存活的分叉。

`SessionProjectionCache.coldState(sessionId, projectionKey, signal?)` 为通过 `SessionProjectionStateMap` 选择的单项状态公开既有检查点、版本失效、身份检查、尾部回放与写回阶梯。这是通用 Host 读取，而不是 token 专用缓存路径，也适用于未来有意不提供客户端 view 的投影。

`@deepseek-ai/dsh-token-usage-report` 是 Host Remote，而不是会话协议扩展。它合并持久化列表与实时会话，同一 id 重复时优先使用实时状态。持久结果按持久化日志 revision 记忆，冷读取受明确配置的并发上限约束。单个会话失败时排除该会话，并计入 `coverage.failedSessionCount`；列表失败、取消、无效 IANA 时区与安全整数溢出会拒绝整个请求。Lifetime 覆盖全部保留样本；每日数据按请求的浏览器时区分组，并限制在包含当天的滚动 365 天窗口内。

浏览器包注册 order 12 的 `token-usage` 设置分区。它把活跃度、趋势与模型作为同一份报告上的独立视图，在 800 像素设置界面中保持紧凑；使用 React 加 SVG/CSS 渲染，不增加图表依赖。活跃度提供每日五档分位单元、按周一至周日汇总并保留首尾不完整周的每周口径，以及从滚动窗口起始日开始的运行累计日历。模型趋势展示最大的五条精确路由加“其他”；页面生命周期内的视觉 registry 保持路由颜色稳定，不同虚实线、点型、tooltip、无障碍文本与可切换图例在没有末端标签时仍让相邻模型不只靠色相区分。模型视图默认排名五条精确路由，并可展开全部路由。页面只在可见时轮询，只允许一个请求进行，释放时取消；后续失败会保留最近一次成功结果并标为陈旧。5/10/30/60 秒选项在与 loopback 等价的本地权限下是普通用户设置；远程浏览器权限禁止 Host namespace 时则只保留在进程内存。

不新增 Session 事件，`SESSION_FORMAT_VERSION` 保持不变。报告只是重建既有提供方用量记录，因此两个 SDK 的会话协议均不变化。

## 考虑过的替代方案

- **从 `session.list` 汇总客户端可见 `tokenUsage` 值**：会丢失日期与路由，排除仅 Host 可见或列表中不可用的状态，也无法移除分叉复制的父前缀。
- **每次刷新都扫描完整日志**：答案相同，却绕过投影检查点，并使轮询成本与全部保留历史等比例增长。
- **估算缺失的提供方用量**：会把压力启发式估算与测量用量混在一起，让总数带上虚假的精度。
- **追加新的 Session 事件或维护可变汇总数据库**：重复记录请求与用量事件已经保存的事实，引入协议或事务一致性问题，并改变删除语义。
- **采用通用图表库**：为了一个紧凑热力图、折线图和排名引入大型依赖，而无障碍与视觉编码行为仍需由本包拥有。

## 后果

历史会话首次生成报告且没有时间线检查点时，会完整回放一次并写回检查点。之后未变化的轮询复用 revision 缓存；日志变化时只回放尾部。存储量按每次模型调用一条紧凑时间线样本增长。单个日志无法读取时，报告可以明确标为不完整；删除分叉历史的原始拥有者会按设计移除对应用量。提供方用量仍是唯一权威，因此适配器未上报用量时，总数可能低于实际流量。

[投影 token 用量决策](2026-07-29-projected-token-usage-and-request-context.zh.md)继续有效：上下文压力与全局用量解决不同问题、采用不同可见性，只共享 token-meter 的提供方用量语义。
